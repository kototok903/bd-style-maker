# Current Discord preview capture

The fixture is captured from the current Discord web client on 2026-10-17, inspected through the user-authorized T3 browser session. It replaces the older Gibbu/ThemePreview snapshot and class aliases. Discord markup, styles, fonts, icons, and other Discord assets belong to Discord and their respective owners; this capture does not relicense them.

`discord-body.html` contains only sanitized sample content. Sanitization runs in the browser on a detached clone, before any HTML is saved: private message/draft text, names, IDs, links, images, data-source attributes, event handlers, and scripts are removed or replaced. SVG mask references are remapped consistently. Structural attributes such as `data-has-border`, layout/density classes, input markup, and inline layout variables are retained because Discord CSS depends on them. The signed-in client's scripts, tokens, cookies, and account APIs are never bundled or connected to the app.

`scripts/capture-discord.js` exports the browser-side capture function. Open a server text channel, close dialogs, wait for transitions, evaluate that function through the browser tool, and save only its returned sanitized HTML and metadata. The capture intentionally refuses to run with an open dialog. Do not save the original live DOM.

`scripts/discord-css-manifest.json` records the ordered public versioned CSS asset URLs, root classes/layout variables, viewport, and structural reference measurements. Run `bun scripts/build-discord-fixture.ts` to rebuild `discord-snapshot.html` from this manifest and sanitized body. The generator downloads the 730 public Discord CSS modules, preserves their order and conditions, rebases asset URLs, embeds the 21 public CSS mask assets and 47 base fonts to avoid cross-origin mask/font failures, and records SHA-256 checksums in `capture.json`. Downloaded sources are cached under `node_modules/.cache/discord-fixture`. The checked-in generated snapshot requires no capture/download step to run the editor.

The app inserts its own CSP and trusted MessageChannel bootstrap. Theme CSS is assigned through a style node's textContent. Form submission and composer input are intercepted; the member-list icon toggles the captured member region locally. ResizeObserver updates the measured user-panel height used by Discord CSS, and the empty composer sizes naturally when theme typography/padding changes. No preview action can send a Discord message or modify an account.

See `docs/preview-validation.json` for structural comparisons with the live client, including MaterialDiscord and system24. The account remains separate from this static fixture; only sample content appears in the app.

The generator embeds these local assets in the snapshot, including folder thumbnails, so icons work with external resources disabled. Folder buttons only expand/collapse local sample markup.

Inspect mode uses `inspector.js` to identify named Discord components and their inner parts, with an escaped DOM-selector fallback for unlisted elements. Clicking pins a component and opens hierarchy, inner-element, state and existing-rule choices in the editor through the private MessageChannel. Breadcrumbs and Alt+Up/Down navigate the hierarchy. Match counts describe the selected selector's DOM matches; hover/focus choices report possible targets without pretending those states are forced. Selecting a state outlines a matching element when present. `Use selector` opens an existing local rule or asks to create a new rule; navigating and picking never modify the theme source. Escape cancels inspection in either the editor or preview. Channel categories and member groups select their headings, because Discord does not wrap their sibling rows in per-group containers.

`sample-content.js` adds trusted static examples of a reply, mention, quote, code block, spoiler, reactions and a typing indicator at bootstrap time, using classes from the captured CSS. Sample spoiler/reaction controls only toggle local classes; inspect mode intercepts them. Member heading counts are split into their native separate label/count spans. No captured account content or client scripts are used for these additions. Menus, user popouts, dialogs and settings still require separate preview scenes.

The same bootstrap curates the channel sidebar to two shortcuts, three text channels and two voice channels across two categories, preserving the three sample voice participants. Inspector captions use a separate viewport-clamped box above or below the outlined element; they do not inherit its width. The editor's inspection hint relocates to another corner when the pointer enters it.

The first sample server has Discord's selected pill classes (`selected__58105` and `visible__58105`). Its always-visible tooltip uses the captured client's tooltip, content and pointer classes in a native layer container. The bootstrap anchors that layer to the server on resize, scrolling and theme/font updates, so the tooltip previews the active theme's own colors, typography and geometry.
